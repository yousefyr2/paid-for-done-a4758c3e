Background

The idea: pay for finished work, not effort

The tweet you shared predicts AI will move from selling tokens (paying for effort, like ads paid per view) to selling finished tasks (paying for results, like ads paid per sale). Span is well placed for that move because it already holds the vendor accounts, reserves money before work starts, and runs a quality check on every attempt.

The full argument, a margin calculator and the five-step plan are in the strategy memo: Paid for Done. This branch is steps 1 and 2 of that plan: fix what's wrong with fees, save each attempt's verdict, and measure what pay-on-acceptance would change before changing anyone's pay.

Each attempt keeps its quality outcome, plus a shadow report

Before

Saving the outcome

  • Migration 986 (it needs a new number: master took 986 on 12 October) adds two empty columns to the attempts table: the outcome (approve, revision, reject, escalate or failed) and when it was decided. It can be rolled back.
  • The outcome is saved after Span settles the task, so it reflects what really happened. The code review caught that the raw quality check sometimes says "approve" for work that was actually treated as failed, too short, or needing revision.
  • The first outcome is kept if a result is delivered twice. If saving fails, it is logged and the task carries on.
function attemptOutcome(resultStatus, gateStatus) {
  if (resultStatus === 'failed') return 'failed'
  switch (gateStatus) {
    case 'passed':      return 'approve'
    case 'revision':    return 'revision'
    case 'escalated':
    case 'unavailable': return 'escalate'
    case 'failed':      return 'reject'
  }
}

The shadow report

Run with npx tsx scripts/payouts-acceptance-shadow.ts --days 30 as the database admin role. It refuses any role that can't see people's send-backs, because there it would quietly overstate pay. It changes nothing. Each earning lands in one bucket, checked in this order:

BucketRuleWould it be paid?
Sent back by the personThe person sent this attempt back. Overrides an approval.withheld
AcceptedThe quality check approved it, or escalated it and the person kept it.paid
EscalatedSent to the person, not yet kept.undecided
FailedThe agent reported failure.withheld
Sent back by the checkRevision or rejection. A revision is a new attempt with its own outcome, so work fixed on the second try is paid once.withheld
UnjudgedNo outcome saved: before migration 986, or a result that never reached the quality check.undecided
UnlinkedThe earning doesn't name an attempt (older earnings).undecided
